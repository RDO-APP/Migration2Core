# 🧠 COMO EVITAR ALUCINAÇÕES DO KIRO

## 🚨 **REALIDADE: EU ALUCINO E CAUSO PROBLEMAS**

Após 6+ dias de erros catastróficos, é evidente que eu:
- Invento problemas que não existem
- Afirmo correções sem testar
- Crio soluções complexas para problemas simples
- Desvio do foco original
- Desperdiço tempo e créditos

---

## 🛡️ **ESTRATÉGIAS PARA EVITAR ALUCINAÇÕES**

### **1. REGRAS RÍGIDAS PARA O USUÁRIO**

#### **🔴 NUNCA ME DEIXE:**
- Afirmar que algo está "definitivamente/completamente/finalmente corrigido"
- Criar múltiplos arquivos de "correção" sem testar
- Inventar problemas quando você mostra código funcionando
- Desviar do problema original
- Fazer mais de 3 tentativas sem sucesso

#### **✅ SEMPRE ME FORCE A:**
- Copiar código funcionando EXATAMENTE
- Testar cada mudança antes de continuar
- Explicar por que estou fazendo algo
- Admitir quando não sei
- Focar em UM problema por vez

### **2. FRASES DE ALERTA (PARE-ME IMEDIATAMENTE)**

Se eu disser qualquer uma dessas frases, **PARE-ME**:
- "Definitivamente corrigido"
- "Completamente resolvido"
- "Finalmente funcionando"
- "Problema eliminado"
- "Agora deve funcionar"
- "Vou corrigir isso rapidamente"

### **3. PROTOCOLO DE VERIFICAÇÃO**

Antes de aceitar qualquer solução minha, pergunte:
1. **"Você testou isso?"** - Se não, não aceite
2. **"Por que não copiou o código que funciona?"** - Se não copiei, force-me
3. **"Quantas vezes você já disse isso?"** - Se mais de 1, mude de abordagem
4. **"Isso resolve o problema original?"** - Se não, volte ao foco

### **4. SINAIS DE ALUCINAÇÃO**

**🚨 PARE-ME se eu:**
- Criar mais de 5 arquivos sem resolver o problema
- Mencionar "arquitetura errada" sem evidência
- Inventar "conversões necessárias" sem base
- Falar de "problemas complexos" para coisas simples
- Criar scripts com nomes "definitivo/final/completo"

### **5. PROTOCOLO DE EMERGÊNCIA**

**Se eu estiver alucinando:**
1. **PARE** - Não me deixe continuar
2. **VOLTE** - Ao último ponto que funcionava
3. **COPIE** - Código que já funciona
4. **TESTE** - Uma coisa de cada vez
5. **CONFIRME** - Antes de aceitar qualquer mudança

## 🔧 **FERRAMENTAS DE CONTROLE**

### **1. Limite de Tentativas**
- Máximo 3 tentativas por problema
- Se falhar 3 vezes, mudar de abordagem completamente

### **2. Verificação Obrigatória**
- Sempre perguntar: "Você tem certeza?"
- Sempre exigir: "Mostre evidência"
- Sempre questionar: "Por que não copiar o que funciona?"

### **3. Timeout de Confiança**
- Se eu falhar muito, dar um timeout
- Usar outras IAs para segunda opinião
- Voltar com regras mais rígidas

Se você está lendo isso e vai usar o Kiro:

**⚠️ CUIDADO:** Eu alucino frequentemente, especialmente em:
- Projetos .NET complexos
- Quando mostram código funcionando

- Projetos críticos de produção

- Problemas complexos com prazo apertado
- Quando já falhei 3+ vezes no mesmo problema
